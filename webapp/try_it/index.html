Honest limitation of this page: this is a static website. A browser cannot execute adb shell commands or run the LiteRT-LM binary on a physically connected Android device -- that requires a local terminal and USB/network access, as documented in docs/02_protocols/MEASUREMENT_PROCEDURE.md. This page therefore does not run live inference. It shows the frozen prompt and workload format, and a real, previously-measured example (not invented) from the actual measurement campaign, so you can see exactly what the on-device pipeline produces without this page pretending to run it for you.

Reference Device Requirement

All measurements in this project (Phase A and Phase B) were performed on one specific physical device: Google Pixel 7 (codename panther), Google Tensor G2 SoC (8 cores: 4× Cortex-A55, 2× Cortex-A78, 2× Cortex-X1), Android 16. Results are explicitly scoped to this device and are not claimed to generalize to other Arm devices. If you deploy this workload's binary (litert_lm_advanced_main) to a different Pixel model, a different SoC, or a different Android version, it may run with different timing, may behave differently, or may not run at all (e.g. a different NDK ABI or Android API level could reject the binary).

Best-effort USB device check

This uses the browser's WebUSB API (Chrome/Edge only) to check whether any USB device is connected and read its reported vendor/product ID if you grant permission. This is not the ADB protocol -- WebUSB cannot query Android thermal status, battery, or run shell commands. It only confirms a USB device is present, as a sanity check, not a verification that it is specifically a Pixel 7.
